## Response Section

### 1. ความหมายของตัวอักษร A, C, I, D

*   **A - Atomicity:** การสร้างข้อมูล Transaction จะเกิดขึ้นได้ก็ต่อเมื่อชุดคำสั่งทั้งหมดต้องทำงานสำเร็จ แต่ถ้ามีคำสั่งใดล้มเหลวจะต้องยกเลิกการสร้างข้อมูล Transaction เพื่อยังคงสภาพข้อมูลก่อนหน้าที่ เหมือนไม่มีอะไรเกิดขึ้น

*   **C - Consistency:** ข้อมูล Transaction ที่สร้างขึ้นมา จะต้องมีความสอดคล้องและถูกต้องตลอดเวลาตั้งแต่ ก่อนสร้างและหลังสร้าง Transaction

*   **I - Isolation:** กระบวนการสร้าง Transaction ต้องเกิดขึ้นโดยลำพัง และห้ามไม่ให้กระบวนการสร้าง Transaction อื่นมารบกวนจนกว่าจะเสร็จสิ้น เพื่อป้องกันการถูกแทรกแซงจนทำให้ข้อมูลผิดเพี้ยนหากมี Transaction เกิดขึ้นพร้อมๆกัน

*   **D - Durability:** หลังจากสร้าง Transaction เสร็จสิ้น ข้อมูลสถานะทั้งหมดจะต้องถูกบันทึกอย่างถาวรเพื่อไม่ให้สูญหาย

### 2. ในความหมายของ ACID ฝั่ง Database และ Application รับผิดชอบเรื่องใด

**1. Database**

*   **A - Atomicity:** การเก็บ Log และการทำ Rollback หากมีข้อผิดพลาดเกิดขึ้น

*   **C - Consistency:** การกำหนดหรือดีไซน์โครงสร้างตาราง Database โดยใช้ PrimaryKey, ForeignKey, DataType, และอื่นๆมาช่วยให้ข้อมูลมีความสอดคล้อง

*   **I - Isolation:** มีการจัดคิวการสร้างหรืออัพเดท Database เพื่อป้องกันการรวบกวนกัน

*   **D - Durability:** การเขียนข้อมูลลง Harddisk หรือ Hardware อื่นที่การันตีว่าข้อมูลจะไม่สุญหาย

**2. Application**

*   **A - Atomicity:** การกำหนดจุดเริ่มต้นและจุดจบของการเปลี่ยนแปลงข้อมูล เช่น การเปลี่ยนแปลงข้อมูลกระทบกี่ตาราง หากชุดคำสั่งไม่สามารถเปลี่ยนแปลงข้อมูลได้ทุกตาราง ต้องมีการย้อนสภาพกลับไปเหมือนไม่มีอะไรเกิดขึ้น

*   **C - Consistency:** การกำหนด Business Logic เช่น เงินในบัญชีธนาคารไม่ควรเป็นเลขติดลบ

*   **I - Isolation:** ทั้งนี้ขึ้นอยู่กับความซับซ้อนของ Business Workflow เช่นระบบจองห้องพักต้องการันตีว่าข้อมูลต้องไม่ถูกรบกวน ระบบนับยอดกด Like ใน Facebook ที่มีการอัพเดท +1 หรือ -1 เท่านั้น

*   **D - Durability:** มี Verify หรือ Acknowledge ที่ยืนยันการันตีจริงๆว่า กระบวนการทำ Transaction ข้อมูลตั้งแต่เริ่มจนจบเส็จสิ้นสมบูรณ์จริงๆ
